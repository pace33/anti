# 에이두 국어 시리즈 구조도

작성일: 2026-05-10  
대상 폴더: `public/aiedu_korean_series`

## 1. 현재 위치와 전체 성격

`에이두 국어 시리즈`는 `aiedue` 프로젝트 안의 정적 웹앱형 학습 프로그램이다. Netlify/Firebase Hosting 기준으로는 `public` 폴더가 배포 루트이며, 국어 시리즈는 그 안의 독립 하위 페이지로 구성되어 있다.

현재 핵심 실행 파일은 `index.html` 하나이며, 화면 마크업, Firebase 연동, 로그인, 대시보드, 학습 단원 데이터, 캔버스 쓰기 활동, 듣기 퀴즈 활동 로직이 대부분 한 파일 안에 들어 있다. 시각 스타일은 `style.css`가 담당하고, 배경 이미지, 로고, 배경음악, 클릭 효과음 같은 자산은 같은 폴더에 함께 배치되어 있다.

## 3. 배포와 실행 구조

`netlify.toml`은 `public`을 정적 배포 폴더로 지정하고, Netlify Functions 위치를 `netlify/functions/`로 지정한다.

```toml
[build]
  publish = "public"
  functions = "netlify/functions/"
```

따라서 국어 시리즈의 예상 접속 경로는 다음과 같다.

```text
/aiedu_korean_series/index.html
```

`firebase.json`도 `public`을 Firebase Hosting 루트로 사용한다. 또한 `/.netlify/functions/generatePlan` 같은 경로를 Firebase Functions로 rewrite하는 설정이 들어 있다.

국어 시리즈 내부의 AI 생성 기능은 브라우저에서 직접 외부 API 키를 쓰지 않고, `/.netlify/functions/generatePlan`을 호출한다. 이 함수는 `GEMINI_API_KEY`, `Stability_api_key`, `GPT_Key` 환경변수에 따라 Gemini, Stability, OpenAI 이미지 생성 요청을 중계할 수 있다. 현재 국어 시리즈에서 직접 쓰는 것은 Gemini 요청이다.

## 4. 핵심 파일별 역할

국어 시리즈의 메인 프로그램이다. 다음 요소가 한 파일에 통합되어 있다.

- HTML 화면 구조
- Tailwind CDN 로드
- `style.css` 로드
- 시작 화면, 로그인 화면, 대시보드, 단계별 활동 화면
- 학생/교사 회원가입 모달
- 설정, 아이콘 선택, 결과 모달
- Firebase Auth/Firestore 연동
- 학습 단원 데이터
- 한글 쓰기 캔버스 활동
- 단어 쓰기 퀴즈
- 듣기 퀴즈
- AI 단어/문장 생성 보조 기능

### `style.css`

국어 시리즈의 공통 디자인 시스템이다.

- 민트/초록 계열 기본 색상 변수
- 태블릿형 메인 카드 레이아웃

- 로그인 카드와 세로 탭
- 대시보드 단계 카드와 슬라이더
- 정보 드로어
- 모달, 애니메이션, 카드 효과

현재 스타일은 `Noto Sans KR`와 `Outfit` 폰트를 Google Fonts에서 가져와 사용한다.

## 7. 로그인과 계정 구조

Firebase Auth와 Firestore를 사용한다. 설정은 `public/firebase-config.js`에서 가져온다.

### 학생 로그인

학생은 숫자 코드로 로그인한다. 내부적으로는 다음 규칙으로 Firebase 이메일/비밀번호를 만든다.

```text
입력 코드: 12
이메일: 12@abc.com
비밀번호: 12qwerty
```

학생 회원가입 시 `metadata/counters` 문서의 `lastUserCode`를 트랜잭션으로 증가시켜 새 숫자 코드를 만든다.

학생 Firestore 문서의 주요 필드는 다음 구조다.

```text
users/{uid}
├─ uid
├─ name
├─ email
├─ userCode
├─ role: "student"
├─ coins
├─ balance
├─ portfolio
├─ aeduExperience
├─ aeduLevel
├─ currentLearningStep
├─ warningTokens
└─ createdAt
```

### 교사 로그인

교사는 이메일/비밀번호 또는 Google 로그인으로 들어간다. Google 로그인 사용자는 `ensureTeacherProfile()`을 통해 교사 프로필 문서가 자동 생성된다.

교사 문서의 주요 필드는 다음 구조다.

```text
users/{uid}
├─ uid
├─ name
├─ email
├─ role: "teacher"
├─ userCode: null
├─ coins
├─ balance
├─ portfolio
├─ aeduTokens
├─ aeduExperience
├─ aeduLevel
├─ warningTokens
└─ createdAt
```

교사는 로그인 후 `currentLearningStep`이 34로 설정되어 전체 학습을 볼 수 있는 구조다.

## 8. 대시보드 권한과 단계 잠금

대시보드에는 1단계부터 4단계까지의 큰 카드가 있다.

```text
1단계: 에이두 그리기
2단계: 에이두 한글 이듬
3단계: 에이두 받아쓰기
4단계: 에이두 문해력
```

`unlockedLevels` 배열로 학생별 접근 가능 단계를 판단한다. 기본값은 현재 `[2]`로 되어 있어 학생은 2단계 중심으로 열리는 구조다. 교사는 항상 `[1, 2, 3, 4]`로 전체 단계가 열린다.

잠긴 단계 카드에는 `locked` 클래스가 붙고, 클릭 시 잠금 안내 모달이 뜬다.

## 10. 배움 상세 콘텐츠 구조

`learningDetailData`는 단계별 설명 콘텐츠다. 현재 배움 1부터 배움 7까지의 상세 데이터가 들어 있다.

각 단계는 다음 구조를 가진다.

```text
learningDetailData[단계번호]
├─ title
├─ subtitle
└─ sections[]
   ├─ label
   ├─ title
   └─ cards[]
```

예를 들어 `배움 1: 모음의 시작`은 다음 흐름이다.

```text
이해하기
├─ 점(ㆍ), 세로선(ㅣ), 가로선(ㅡ)의 모양 관찰
└─ 해, 사람, 땅 그림과 연결해 ㆍ, ㅣ, ㅡ의 의미 찾기

이렇게 글자가 만들어져요
├─ ㅣ + ㆍ → ㅏ
└─ ㆍ + ㅣ → ㅓ
```

배움 상세 화면은 섹션 단위로 `다음` 버튼을 눌러 이동하고, 마지막 섹션에서 `완료`를 누르면 Firestore의 `currentLearningStep`이 갱신된다.

## 11. 한글 활동 세부 기능

### 나의 한글

`openMyKoreanSection()`에서 열린다. 단원 탭과 학습 목록을 보여준다.

주요 기능:

- 단원 탭 렌더링
- 배움 목록 렌더링
- 완료/열림/잠김 상태 표시
- 이미 완료한 활동은 복습 가능
- 다음 활동은 시작 가능

### 오늘의 한글

`openTodayKoreanActivity()`에서 열린다. 사용자의 `currentLearningStep`을 기준으로 다음 배움 활동을 자동으로 연다.

```text
currentLearningStep = -1 → 배움 시작 활동
currentLearningStep = 0  → 배움 1
currentLearningStep = 1  → 배움 2
...
```

### 글자 쓰기

`initializeLetterWritingActivity()`에서 초기화된다.

구성:

- 자음: ㄱ, ㄴ, ㄷ, ㄹ, ㅁ, ㅂ, ㅅ, ㅇ, ㅈ, ㅊ, ㅋ, ㅌ, ㅍ, ㅎ
- 모음: ㅏ, ㅓ, ㅗ, ㅜ, ㅡ, ㅣ
- 낱말/음절: 가, 나, 다, 라, 마, 바, 사, 아
- 캔버스 점선 가이드
- 손가락/마우스 쓰기
- 음성 읽기
- 픽셀 겹침 비율 기반 간단 채점
- AI 단어/문장 생성 보조

채점은 정답 글자 가이드 픽셀과 사용자가 그린 픽셀의 겹침 비율을 계산한다. 현재 기준은 약 40% 이상이면 정답으로 판단한다.

### 낱말 쓰기 퀴즈

`initializeWordWritingQuizActivity()`에서 초기화된다.

모드:

```text
음절 쓰기
├─ 받침 없음: 가, 너, 보, 소
└─ 받침 있음: 각, 산, 밥, 몸

낱말 쓰기
├─ 2글자: 나무, 학교
└─ 3글자: 바나나, 호랑이

내 이름 쓰기
└─ 사용자가 입력한 이름을 가이드로 표시
```

글자 쓰기와 마찬가지로 캔버스 위에 회색 가이드 글자를 보여주고, 사용자가 따라 쓴 뒤 픽셀 겹침 비율로 채점한다. 현재 기준은 약 45% 이상이면 정답이다.

### 낱말 듣기 퀴즈

`initializeListeningQuizActivity()`에서 초기화된다.

카테고리:

```text
받침없는 낱말 (ㅏ,ㅣ..)
받침있는 낱말 (ㅏ,ㅣ..)
받침없는 낱말 (ㅑ,ㅘ..)
받침있는 낱말 (ㅑ,ㅘ..)
쉬운 단어
쉬운 문장
어려운 단어
어려운 문장
```

작동 방식:

1. 사용자가 카테고리와 문제 수를 선택한다.
2. Gemini에 JSON 형식의 퀴즈 생성을 요청한다.
3. 브라우저 SpeechSynthesis가 정답 단어/문장을 읽어준다.
4. 사용자는 보기 3개 중 하나를 선택한다.
5. 마지막에 점수와 메시지를 보여준다.

## 12. 교사 학급 관리

교사 계정에는 정보 드로어 안에 `학급 관리하기` 버튼이 나타난다.

학급 관리는 `class-management-modal`을 사용한다.

현재 로직:

- `classes/{teacherUid}` 문서에서 `students` 배열을 읽는다.
- 배열의 학생 uid로 `users/{studentUid}` 문서를 가져온다.
- 학생 이름, 로그인 번호, 단계별 잠금 토글을 표시한다.
- `unlockedLevels` 배열에 1~4단계 숫자를 추가/삭제해 접근 가능 단계를 조절한다.

학생 추가 로직은 현재 이름으로 학생을 검색해 `teacherId`를 지정한다. 다만 목록 로딩은 `classes/{teacherUid}.students` 배열을 기준으로 하므로, 학생 추가 후 학급 목록에 바로 보이려면 `classes` 문서의 students 배열 갱신 로직도 함께 맞춰야 한다.

## 13. 공통 UI 상태 관리

화면 전환은 주로 다음 함수들이 담당한다.

```text
showTopLevelSection(sectionId)
setTopLevelSectionVisible(sectionId, isVisible)
hideAllActivitySections()
showDashboardOnly()
openDashboard()
enterLevel(level)
```

활동 열기 함수는 대부분 `open...Activity()` 형태로 선언되어 있다.

```text
openLetterWritingActivity()
openWordWritingQuizActivity()
openWordListeningQuizActivity()
openMyKoreanFromDashboard()
openTodayKoreanActivity()
```

사용자 정보 동기화는 `updateDashboardExperience(userData)`가 중심이다. 이 함수는 이름, 아이콘, 코인, 역할, 현재 학습 단계, 단계 잠금 상태를 대시보드와 드로어에 반영한다.

## 14. 소리와 음성

프로그램에는 두 종류의 소리 기능이 있다.

### 배경음악/효과음

`aiedu_bgm.mp3`, `aiedu_click.mp3`가 `<audio>` 태그로 들어가 있다.

```text
#bg-music      배경음악, loop
#click-sound   클릭 효과음
```

`toggleMute()`로 음소거 상태를 바꾸고, 전역 클릭 이벤트에서 버튼/카드 클릭 시 `playClickSound()`가 호출된다.

### 학습 음성

한글 읽기와 듣기 퀴즈는 브라우저 내장 `SpeechSynthesisUtterance`를 사용한다.

```text
utterance.lang = "ko-KR"
```

서버 TTS가 아니라 브라우저 음성 합성이므로 사용자의 브라우저/운영체제에 따라 음성 품질이 달라질 수 있다.

## 16. 현재 구현상 주의할 점

1. `index.html`에 화면, 데이터, Firebase 로직, 활동 로직이 모두 들어 있어 파일이 매우 크다. 이후 콘텐츠가 늘어나면 유지보수를 위해 모듈 분리가 필요하다.

2. 한글 시리즈 파일을 PowerShell에서 기본 인코딩으로 읽으면 일부 한글이 깨져 보일 수 있다. 파일 자체는 UTF-8 기준으로 다루는 것이 안전하다.

3. 교사 학생 추가 로직은 `users` 문서의 `teacherId`만 수정하고, 학급 목록 로딩은 `classes/{teacherUid}.students` 배열을 기준으로 한다. 두 데이터 구조를 통일해야 교사 학급 관리가 안정적으로 동작한다.

4. 학생 기본 `unlockedLevels`가 `[2]`로 되어 있어 2단계만 열리는 설계다. 의도한 시작 단계가 1단계라면 기본값 조정이 필요하다.

5. `learningDetailData`는 현재 배움 1~7 중심으로 상세 콘텐츠가 있고, 8 이후 단계는 목록은 있으나 상세 콘텐츠 확장이 필요하다.

6. 캔버스 채점은 픽셀 겹침 기반의 간단 채점이다. 실제 아동 학습 환경에서는 획순, 글자 위치, 허용 오차, 부분 점수 기준을 더 정교하게 만들 수 있다.

7. 듣기 퀴즈는 Gemini 응답 JSON을 그대로 파싱한다. 응답 형식이 깨지면 오류가 날 수 있으므로 예외 처리와 기본 문제 세트가 더 필요하다.

8. 일부 1단계/3단계/4단계 버튼은 현재 완성 활동이 아니라 준비 중 안내 성격으로 연결되어 있다.

## 17. 다음 작성 작업 제안

국어 시리즈 내용을 본격적으로 작성할 때는 다음 순서가 자연스럽다.

```text
1. 전체 4단계의 학습 목표 확정
2. 2단계 한글 단원의 배움 8~34 상세 콘텐츠 추가
3. 1단계 그리기 활동의 실제 활동 화면 작성
4. 3단계 받아쓰기 문제 구조 작성
5. 4단계 문해력 읽기 자료/문항 구조 작성
6. 교사 학급 관리 데이터 구조 정리
7. index.html 기능을 JS 모듈로 분리
```

현재 프로그램은 이미 시작 화면, 로그인, 대시보드, 2단계 한글 학습 뼈대, 캔버스 쓰기 활동, 듣기 퀴즈까지 갖춘 상태다. 다음 단계의 핵심은 “콘텐츠 데이터 확장”과 “활동별 화면 완성도 향상”이다.
